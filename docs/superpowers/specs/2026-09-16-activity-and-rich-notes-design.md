# Activity tracker and rich notes — design

Date: 2026-09-16. Extends `2026-09-12-second-brain-design.md`; that document's architecture, stack, copy rules, and visual direction bind here unless overridden.

## 1. Purpose

Two additions to the second brain:

1. **Activity tracker.** Automatically records where time goes on the Mac: which app is frontmost, which window or site, when the user is away, and which calendar meeting or interview a call belongs to. The user sees a day timeline and totals, a week view, and a meetings list, and can turn any call into a meeting note.
2. **Rich notes.** A Notion-style block editor replaces the plain textarea wherever the user writes markdown, while storage stays markdown so search, embeddings, the assistant, and backups are unchanged.

Both stay local. Nothing leaves the machine.

## 2. Activity tracker

### 2.1 Helper process

- Location: `helpers/activity/` (Swift Package, executable target `sb-activity`, macOS 13+). Built by `swift build -c release` from `scripts/brain.sh setup`; the binary is copied to `DATA_DIR/bin/sb-activity`.
- Run by a launchd agent `com.second-brain.activity`, installed alongside `com.second-brain.app` by `scripts/brain.sh setup` and managed by `start`, `stop`, `restart`, and `status`.
- Every 5 seconds it samples:
  - frontmost app: bundle id and localized name via `NSWorkspace.shared.frontmostApplication`;
  - window title via the Accessibility API (`AXUIElement` focused window, `kAXTitleAttribute`);
  - active tab URL when the app is Google Chrome, Arc, Brave, Microsoft Edge (Chromium AppleScript dictionary) or Safari, via `NSAppleScript`;
  - idle seconds via `CGEventSource.secondsSinceLastEventType(.combinedSessionState, eventType: .null)`.
- It posts a heartbeat to `POST http://127.0.0.1:3141/api/activity/heartbeat` with header `Authorization: Bearer <token>`, where the token is a random 32-byte hex string generated by setup into `DATA_DIR/activity-token`. Body:

```json
{ "at": "2026-09-16T10:15:05Z", "app_id": "com.microsoft.VSCode", "app_name": "Code",
  "title": "item-editor.tsx — second-brain", "url": null, "idle_seconds": 2 }
```

- Idle above 180 seconds sends `{ "at": ..., "afk": true }` instead, once per 5 seconds, until activity resumes.
- Once a minute it posts today's and tomorrow's calendar events read via EventKit to `POST /api/activity/calendar`: `{ events: [{ external_id, title, starts_at, ends_at, attendees, has_call_link }] }`. `has_call_link` is true when the location, URL, or notes contain a Zoom, Meet, Teams, or Webex link. Attendees is a count.
- The heartbeat response returns `{ exclusions: { apps: string[], domains: string[] }, paused: boolean }`. The helper drops samples whose app id or URL host matches an exclusion before they are sent, and sends nothing while paused except one `paused` heartbeat per minute so the UI can show state.
- If the server is unreachable the helper buffers up to 12 hours of heartbeats in memory, retries every 30 seconds, and flushes in order when the server returns.
- `sb-activity --once` prints a single sample as JSON and exits with a non-zero code naming any missing permission (`accessibility`, `automation:<browser>`, `calendar`). Setup runs it to report status.
- Permissions: Accessibility (window titles), Automation per browser (URLs), Calendar. The helper triggers each system prompt on first use. The Activity page reads the helper's last reported permission state and offers a button per missing permission that runs `open "x-apple.systempreferences:com.apple.preference.security?Privacy_<Pane>"`.

### 2.2 Data model

New tables via drizzle migrations.

```
activity_categories: id, name (unique), color (hex), sort_order
activity_rules:      id, match_kind ('app' | 'domain' | 'title_contains'), pattern, category_id → activity_categories, sort_order
activity_exclusions: id, kind ('app' | 'domain'), pattern (unique with kind)
activity_sessions:   id, started_at, ended_at, app_id, app_name, title, url, domain,
                     category_id → activity_categories (set null), afk (0|1),
                     meeting_id → calendar_events (set null), heartbeats (count)
calendar_events:     id, external_id (unique), title, starts_at, ends_at, attendees, has_call_link, day (YYYY-MM-DD)
settings keys:       activity_paused ('0'|'1'), activity_retention_days (default '90'), activity_helper_state (JSON: last_seen, permissions, version)
```

Timestamps are ISO-8601 UTC strings like the rest of the schema. `domain` is the URL host with a leading `www.` stripped.

Seeds (inserted once by the migration, editable by the user):

- Categories: Coding `#4cc9ff`, Meetings `#f5c451`, Communication `#52d38a`, Browsing `#9b9ba4`, Writing `#c084fc`, Leisure `#ff5c6c`, Other `#62626b`.
- Rules, in order: app `com.microsoft.VSCode` → Coding; app `com.apple.Terminal`, `com.googlecode.iterm2`, `dev.warp.Warp-Stable` → Coding; domain `github.com`, `gitlab.com` → Coding; app `us.zoom.xos`, `com.microsoft.teams2`, `com.webex.meetingmanager` → Meetings; domain `meet.google.com`, `zoom.us` → Meetings; app `com.tinyspeck.slackmacgap`, `com.apple.mail`, `com.apple.MobileSMS`, `com.hnc.Discord` → Communication; domain `mail.google.com`, `slack.com` → Communication; app `com.apple.Notes`, `md.obsidian`, `com.apple.iWork.Pages` → Writing; domain `youtube.com`, `netflix.com`, `reddit.com`, `twitter.com`, `x.com` → Leisure; app `com.apple.Safari`, `com.google.Chrome`, `company.thebrowser.Browser`, `com.brave.Browser`, `com.microsoft.edgemac` → Browsing (catch-all for browsers after domain rules).
- Exclusions: apps `com.1password.1password`, `com.agilebits.onepassword7`, `com.bitwarden.desktop`, `com.apple.keychainaccess`; domains `*.bank`, `chase.com`, `bankofamerica.com`, `wellsfargo.com`, `paypal.com`, `accounts.google.com`, `login.microsoftonline.com`. Domain patterns support a leading `*.` wildcard.

### 2.3 Session folding

Implemented in `src/domain/activity/`.

- `ingestHeartbeat(hb)`: loads the open session (latest with `ended_at` null). If the heartbeat is `afk`: close the open session at the heartbeat time and open an `afk` session if none is open. Otherwise compute the sample key `(app_id, domain ?? '', title)`. If the open session is `afk`, close it and open a new one. If the key equals the open session's key, extend `ended_at` and increment `heartbeats`. If only the title differs, and the previous title change was under 20 seconds ago, update the title in place (tab flicker debounce) instead of splitting. Otherwise close the open session at the heartbeat time and open a new one at the same instant.
- Gap rule: if the heartbeat is more than 15 minutes after the open session's `ended_at`, close it at `ended_at` (do not extend across sleep) and open a new session.
- Category is assigned on open by `evaluateRules(rules, sample)`: rules in `sort_order`, first match wins; `app` matches `app_id` exactly, `domain` matches the host or any parent domain, `title_contains` matches case-insensitively. No match → Other.
- Meeting label: on open, if the category is Meetings, find a `calendar_events` row whose interval overlaps the heartbeat time, preferring the one with `has_call_link`; set `meeting_id`. If the event title contains "interview" (case-insensitive) the timeline shows an Interview tag; no extra column.
- Exclusion check is repeated server-side (`isExcluded`) so a stale helper cannot store an excluded sample.
- `pruneSessions()` deletes sessions and calendar events older than `activity_retention_days`; runs from the existing nightly backup job.
- `recategorise(days)` re-evaluates rules over the last N days; called after the user edits rules.

### 2.4 API

All under `src/app/api/activity/`. Heartbeat and calendar routes require the bearer token; the rest are same-origin like existing routes.

| Route | Purpose |
|---|---|
| `POST /heartbeat` | ingest one heartbeat; returns exclusions and paused |
| `POST /calendar` | replace events for the days present in the payload |
| `GET /day?date=YYYY-MM-DD` | sessions (non-afk, merged for display), totals by category, app, and domain, meetings with scheduled vs actual minutes, helper state |
| `GET /week?start=YYYY-MM-DD` | per-day category totals |
| `GET/POST /rules`, `PATCH/DELETE /rules/[id]` | rules CRUD plus reorder; POST and PATCH trigger `recategorise(30)` |
| `GET/POST/DELETE /exclusions` | exclusion list |
| `GET/PATCH /categories` | rename or recolour |
| `POST /pause` | toggle `activity_paused` |
| `POST /sessions/[id]/label` | set or clear `meeting_id` by hand |
| `POST /meetings/[eventId]/capture` | create a `meeting` item titled after the event with attendees and times in the body; links back via the item's `meta.calendar_event_id` |

Zod schemas live in `src/lib/validation.ts`; DTOs in `src/lib/dto.ts`.

### 2.5 UI

- Dock entry **Activity** (icon `Activity`), shortcut `g t`, placed after People. The entry shows a small red dot when the helper has not reported for over 2 minutes and recording is not paused.
- `/activity` page, client component with the day as a query parameter:
  - Header: `PageHeader` with the date, previous and next `IconButton`s, a "Today" button, the day's active total in mono, and a `Chip` toggle "Paused".
  - Status strip under the header when something needs attention: "Not recording since 14:02: helper not running" or "Window titles unavailable: grant Accessibility" with a button that opens the settings pane.
  - **Timeline**: a 24-hour bar, one row, sessions as coloured blocks by category, afk in the faint surface colour, hover shows app, title or site, and duration; click opens a small popover to relabel the session's category or meeting. Categories legend beneath.
  - **Totals**: three columns (category, app, site or window), each a `List` of rows with a proportional bar in the accent-dim tint and the duration in mono.
  - **Meetings**: rows per calendar event of the day: title, scheduled span, actual minutes in a call app, attendees count, an Interview tag when applicable, and a "Capture as meeting note" `Button`; once captured, a link to the item instead.
  - **Week** tab: seven stacked bars by category with the daily totals; clicking a day navigates to it.
  - **Rules** drawer (`frost` panel from the right): ordered rules with drag reorder, add rule form (kind, pattern, category), exclusions list, category colours, retention days. Saving rules re-categorises the last 30 days and refreshes.
- Journal integration (when the journal slice lands): the read-only panel shows the day's category totals.

### 2.6 Errors

- Helper unreachable: page shows the last heartbeat time and reason; nothing else degrades.
- Missing permission: helper still records what it can (app-only when Accessibility is missing) and reports the gap; the page names it.
- Clock jumps and sleep: handled by the 15-minute gap rule; a session never extends across a gap.
- Duplicate or out-of-order heartbeats: any heartbeat older than the open session's `ended_at` is ignored.
- Bad token: 401, logged once per minute at most.

### 2.7 Testing

Vitest in `src/domain/activity/*.test.ts` and `src/app/api/activity/*.test.ts` using the existing in-memory database helper:

- folding: same key extends; key change splits at the heartbeat time; title flicker under 20 s updates in place; afk closes and reopens; 15-minute gap closes at the last `ended_at`; out-of-order heartbeat ignored;
- rules: order wins; parent domain matches; `title_contains` case-insensitive; no match → Other; `recategorise` rewrites categories;
- meetings: overlap sets `meeting_id`, call-link event preferred; interview detection;
- exclusions: wildcard domains; server-side drop;
- prune: retention boundary;
- API: 401 without token; day totals sum to session durations; capture creates a meeting item once (second call returns the existing item).
- Swift: no automated tests; `sb-activity --once` is the manual check, run by setup.

## 3. Rich notes

### 3.1 Editor

- `src/components/editor/rich-editor.tsx` exports `RichEditor({ value, onChange, onBlur, placeholder, autofocus?, className? })`. It is a client component built on `@tiptap/react` with: StarterKit (paragraph, headings 1–3, bold, italic, strike, code, bullet and ordered lists, blockquote, code block, horizontal rule, hard break, history), `@tiptap/extension-task-list` and `task-item`, `@tiptap/extension-table` with row, cell, and header, `@tiptap/extension-link` (auto-link on paste, opens in new tab), `@tiptap/extension-image`, `@tiptap/extension-placeholder`, `@tiptap/extension-code-block-lowlight` for syntax colouring, a custom `Callout` node, a custom `SlashMenu` extension, and `tiptap-markdown` for serialisation.
- Content contract: `value` is markdown; `onChange(markdown)` fires after the document changes, debounced 300 ms inside the component so callers see a string, not a ProseMirror transaction. The item editor keeps its own 800 ms save debounce, `markDirty`, blur flush, unmount flush, and ⌘S unchanged.
- Markdown shortcuts while typing: `#`, `##`, `###`, `-`, `*`, `1.`, `[ ]`, `> `, three backticks, `---`, `**bold**`, `*italic*`, backtick code.
- Slash menu on `/` at the start of an empty block or after a space: Heading 1–3, Bulleted list, Numbered list, Checklist, Quote, Code, Table (3×3), Image, Callout, Divider. Filtered as the user types; arrow keys and Enter select; Escape closes.
- Bubble menu on selection: Bold, Italic, Code, Strikethrough, Link (with an inline URL input).
- Block drag handle appears at the left of the hovered block; dragging reorders blocks.
- Tab and Shift+Tab indent and outdent list and task items.
- Callout serialisation: a blockquote whose first paragraph starts with `[!note]`, `[!tip]`, or `[!warning]`; the editor renders it as a tinted box with an icon and hides the marker. Any other blockquote stays a quote.
- Tables serialise as GFM pipe tables; cells are inline-only.
- Unsupported markdown (raw HTML blocks, footnotes) round-trips as a fenced code block labelled `html` or `markdown` so nothing is lost.

### 3.2 Attachments

- Table `attachments`: id, item_id → items (cascade delete), filename, mime, bytes, created_at.
- Files live at `DATA_DIR/attachments/<item_id>/<attachment_id>-<safe-filename>`.
- `POST /api/attachments` (multipart: `itemId`, `file`; image types only: png, jpeg, gif, webp, svg is rejected; 20 MB cap) returns `{ id, url: "/api/attachments/<id>" }`.
- `GET /api/attachments/[id]` streams the file with its mime type and a one-year cache header.
- `deleteItem` removes the item's attachment directory after the row cascade.
- In the editor, pasting or dropping an image inserts a placeholder block, uploads, then swaps in the image node with the returned URL; on failure the placeholder shows "Upload failed" with Retry and Remove. Non-image files dropped on the editor are sent through the existing `/api/upload` capture flow and a link to the new item is inserted.
- Nightly backup copies `DATA_DIR/attachments` alongside the database (the existing backup job gains a directory copy with the same 7-day retention).

### 3.3 Where the editor appears

- Item page body for every item type; the preview toggle stays and renders the same markdown through the existing renderer.
- Container editor: description and next steps.
- Person editor: profile.
- Capture page keeps the plain textarea: capture is for speed, the editor is for shaping.
- Journal, meeting notes, and weekly review adopt it when those slices land.

### 3.4 Styling

The editor's content area uses the existing `.md` styles so edit and read modes match. Additions: task checkboxes styled with the accent, callouts tinted per kind (note uses accent-dim, tip uses success at 14%, warning uses warn at 14%), table borders on `--color-line`, a faint drag handle, and slash and bubble menus in `frost` panels using the `Kbd`, `Row`, and `IconButton` primitives. Copy rules from the polish plan apply to every label.

### 3.5 Errors

- Editor fails to mount (extension error): the component catches it and renders the plain textarea with the same props; an error banner reads "Rich editor unavailable, using plain text."
- Markdown that changes when round-tripped without edits: the editor does not emit `onChange` until the user types, so opening and closing a note never rewrites it.

### 3.6 Testing

- `rich-editor.test.ts` (jsdom): a fixture corpus in `src/components/editor/fixtures/*.md` covering each block, nested lists, checklists, tables, callouts of each kind, code with a language, images, links, and an HTML block; each fixture must round-trip byte-identical after normalisation (trailing whitespace and a final newline).
- Attachment API tests: upload accepts png and rejects svg and oversize; GET streams the right mime; deleting the item removes the row and the file.
- Item editor test: typing through `RichEditor` produces the same ordered PATCH bodies as the textarea did (mock fetch, assert bodies).

## 4. Scripts and running

- `scripts/brain.sh setup` builds the helper (requires Xcode command line tools; prints a clear message if `swift` is missing and continues without the tracker), writes the token, installs both agents, and runs `sb-activity --once` to report permissions.
- `start`, `stop`, `restart`, `status` act on both agents; `status` prints the helper's last heartbeat age and permission state from `activity_helper_state`.
- README gains an "Activity tracking" section: what is recorded, the three permissions, exclusions, pause, retention, and how to uninstall the helper (`scripts/brain.sh stop && launchctl unload …`).
