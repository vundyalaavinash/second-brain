# Focus Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A countdown bound to a task, whose minutes are booked against that task — so the app finally learns what work actually costs.

**Architecture:** One new table, `focus_runs`, and one domain module, `src/domain/focus/index.ts`. A run is a database row with a start, a planned length and — once finished — an end, an actual length and an outcome. There is no process and no timer on the server: the countdown is arithmetic the browser does from `startedAt + plannedMinutes`, so a reload resumes it exactly. A run left running past its planned end because the browser was closed is reconciled on the next read, closed at the end it was meant to have. The dock carries the chip; the task detail carries what the minutes bought.

**Tech Stack:** Next.js 16 App Router, React 19 (react-compiler lint: no synchronous `setState` in effect bodies), Tailwind 4 Carbon tokens, Drizzle + better-sqlite3 (`npx drizzle-kit generate --name <name>`), zod 4, Vitest 5 jsdom, `motion` 12.

**Spec:** `docs/superpowers/specs/2026-09-24-closing-the-loop-design.md` (§4, §6, §7)

## Global Constraints

- Carbon tokens only — `src/test/tokens.test.ts` fails on `ink`, `slate`, `brass`, `paper`, `tone=`, `on-paper`, `shadow-dock`. Sentence case. `focus-ring` on every interactive element. `aria-label` on icon-only controls.
- No synchronous `setState` in an effect body (react-compiler lint). Use a ref, `queueMicrotask`, or an event handler.
- Tests never touch the network, and never depend on real elapsed time. Every domain function that needs the clock takes `now: Date` as an argument with a default.
- Migrations: `npx drizzle-kit generate --name <name>`; never hand-edit the journal or snapshot.
- Outcomes are exactly `completed`, `stopped`, `abandoned`. Only `completed` and `stopped` contribute minutes.
- **The abandon rule:** a run finished under **2 minutes** after its start is `abandoned` whatever outcome was asked for, and books zero minutes. `ABANDON_UNDER = 2` is an exported constant.
- **One run at a time.** Starting a run while another is live stops the older one as `stopped` (or `abandoned`, if the abandon rule catches it) in the same transaction.
- **Reconciliation:** a run read back whose planned end passed more than **30 minutes** ago (`STALE_AFTER = 30`) is closed at its planned end as `completed`. A run still inside that grace period is returned as live.
- Focus settings live under the settings key `focus`, a JSON object `{ defaultMinutes, shortBreak, longBreak, longBreakEvery }` defaulting to `{ 25, 5, 15, 4 }`.

```ts
/**
 * One stretch of focused work on a task. There is no timer on the server: a live run is a row
 * with no end, and the countdown is arithmetic from its start, so a reload resumes it exactly
 * where it was and a closed browser loses nothing.
 */
export const focusRuns = sqliteTable(
  "focus_runs",
  {
    id: integer("id").primaryKey({ autoIncrement: true }),
    taskId: integer("task_id")
      .notNull()
      .references(() => tasks.id, { onDelete: "cascade" }),
    /** The session this run was started from, when it was started from one. */
    blockId: integer("block_id").references(() => taskBlocks.id, { onDelete: "set null" }),
    startedAt: text("started_at").notNull(),
    /** Null while the run is live. */
    endedAt: text("ended_at"),
    plannedMinutes: integer("planned_minutes").notNull(),
    /** Null while the run is live; zero for an abandoned one. */
    actualMinutes: integer("actual_minutes"),
    outcome: text("outcome", { enum: FOCUS_OUTCOMES }),
  },
  (t) => [index("focus_runs_task_idx").on(t.taskId), index("focus_runs_started_idx").on(t.startedAt)],
);
export type FocusRun = typeof focusRuns.$inferSelect;
```

`startedAt` and `endedAt` are UTC ISO instants, the same spelling `tasks.completedAt` uses — not the local `LocalTimestamp` spelling `task_blocks.startsAt` uses. A run is a moment, not a wall-clock slot.

- [ ] **Step 4: Write the domain module**

The two rules worth care:

**Starting stops the incumbent, in one transaction.**

```ts
export function startFocus(db: DB, input: { taskId: number; blockId?: number | null; minutes?: number }, now = new Date()): FocusRun {
  if (!getTask(db, input.taskId)) throw new FocusError("Task not found", 404);
  const minutes = input.minutes ?? getFocusSettings(db).defaultMinutes;
  if (!Number.isInteger(minutes) || minutes < 5 || minutes > 480) throw new FocusError("A run is 5 to 480 minutes");
  return db.transaction((tx) => {
    // One run at a time: the incumbent keeps whatever it has actually run.
    const live = liveRow(tx);
    if (live) closeRow(tx, live, "stopped", now);
    return tx
      .insert(focusRuns)
      .values({ taskId: input.taskId, blockId: input.blockId ?? null, startedAt: now.toISOString(), plannedMinutes: minutes })
      .returning()
      .get();
  });
}
```

**Closing applies the abandon rule in one place**, so no caller can book a two-minute run:

```ts
function closeRow(tx: DB, run: FocusRun, outcome: FocusOutcome, now: Date): FocusRun {
  const ran = Math.max(0, Math.round((now.getTime() - Date.parse(run.startedAt)) / 60_000));
  // Under two minutes is a mis-click, not work: it is abandoned whatever it was called, and
  // books nothing, so a day's figure is never inflated by runs nobody actually sat through.
  const settled = ran < ABANDON_UNDER || outcome === "abandoned" ? "abandoned" : outcome;
  return tx
    .update(focusRuns)
    .set({ endedAt: now.toISOString(), actualMinutes: settled === "abandoned" ? 0 : ran, outcome: settled })
    .where(eq(focusRuns.id, run.id))
    .returning()
    .get();
}
```

`runningFocus` reconciles first:

```ts
export function runningFocus(db: DB, now = new Date()): FocusRun | null {
  const live = liveRow(db);
  if (!live) return null;
  const plannedEnd = Date.parse(live.startedAt) + live.plannedMinutes * 60_000;
  // A browser closed mid-run leaves the row open forever. Past the grace period the run is
  // closed at the end it was meant to have, not at now: crediting hours nobody worked would
  // make every figure that reads this a lie.
  if (now.getTime() - plannedEnd > STALE_AFTER * 60_000) {
    closeRow(db, live, "completed", new Date(plannedEnd));
    return null;
  }
  return live;
}
```

`focusWhere(db, run)` reads `getDay(db, localDay(run.startedAt)).sessions`, keeps the non-AFK ones overlapping the run's window, sums the overlap per app — naming a browser by its busiest domain exactly the way `activityToday` in `src/lib/home.ts` already does — and returns the top three. Read that function and match its rule rather than writing a second one; if the rule is worth sharing, lift it into `src/domain/activity` and have both call it.
